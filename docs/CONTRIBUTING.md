# 协作规范

本文件约定 TaskFlow 项目的提交、分支与评审规则，用于保证多人协作时历史清晰、可追溯。

## 1. 提交信息规范

格式：`<type>: <简短描述>`

| type | 含义 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 缺陷修复 |
| `docs` | 文档变更 |
| `style` | 仅格式调整，不影响逻辑 |
| `refactor` | 重构，不改变外部行为 |
| `chore` | 构建、依赖、脚手架等杂项 |

要求：

- 描述使用中文，动词开头，不超过 50 字
- 一次提交只做一件事，避免「顺手改」混入无关改动
- 涉及 Issue 时在提交或 PR 描述中用 `Closes #编号` / `Fixes #编号` 关联

## 2. 分支模型

```
main
 ├── feature/xxx   功能开发
 └── hotfix/xxx    线上缺陷修复
```

- `main` 始终保持可运行，禁止直接 push，只能通过 Pull Request 合入
- 分支命名使用小写英文与短横线，例如 `feature/task-filter`
- 分支合并后及时删除，避免堆积

## 3. Pull Request 要求

- 标题与主要提交保持一致的 `type: 描述` 格式
- 描述中说明「改了什么 / 为什么改 / 怎么验证」
- 必须关联对应 Issue
- 自测通过后再提交评审；合并方式统一使用 Merge commit，保留分支决策痕迹

## 4. 不应提交的内容

`node_modules/`、`dist/`、编辑器配置、`.env` 等已在 `.gitignore` 中排除。提交前用 `git status` 确认暂存区内容，避免把本地环境文件带进仓库。
